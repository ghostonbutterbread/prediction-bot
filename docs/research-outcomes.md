# Post-seal research outcome binding

`scripts/prepare_research_outcomes.py` connects the existing source-only comparison, canonical outcome binder and independent research-feedback scorer. It does not run a collector, fetch data, modify the source resolution ledger, update accounts, or activate a strategy.

Run **after** trusted baseline/candidate code has finished on an empty outcome file and a trusted `auto_research.py compare` reports matching selected rows. This requires the integrated daily comparator (including `input_sha256` and `outcome_sha256` in its receipt); older comparators without those fields cannot be used. Pass that unmodified comparison receipt, the exact frozen replay inputs and a separate retained resolution file with a caller-provided SHA-256. The helper requires two distinct experiments, a nonzero matched count, and each run's seen/control/candidate counts equal to that count with zero invalid identities. Every nonblank input line must be a JSON object, and the total must equal the matched count. **A larger file from a `--max-rows` subset is rejected**, not silently bound: prepare the complete selected feed page as the frozen input and rerun both experiments and comparison on that page. Do not truncate a file after comparison: its hash will no longer match.

The helper checks the input hash against the comparison and the original outcome hash against the empty-file hash, then calls the existing binder. It checks the input, comparison and resolution hashes before/after binding and compares them with the binder's recorded hashes. The three files must be physically distinct, including hardlinks. It writes a new report directory beneath `data/derived_reports` and refuses existing destinations. Provide stable, immutable input and resolution artifacts and a stable trusted namespace: identity and before/after hash checks are not locks against concurrent path replacement, and size limits are preflights, not hard memory/read bounds against concurrent mutation or producer authentication.

A completed output contains `receipt.json`, `binding/finalized_replay_outcomes.jsonl`, `binding/unbound_replay_inputs.jsonl` and the binder's metadata. Point `scripts/research_feedback.py --outcomes` at the bound output and pass the `outcomes_sha256` from the receipt. If the source feed has no valid outcomes, binding succeeds with zero bound and explicit unbound counts; report that as waiting, not successful learning. Use a **new** output directory for a later changed resolution set; preserve previous results. An interrupted or failed invocation may leave an incomplete destination with a missing or partial completion receipt. Do not reuse or delete it automatically; inspect and retry with a new owned directory.

The comparison receipt and files must themselves be protected from experimental code. A caller can forge both a comparison and its files; matching hashes do not authenticate a producer, show an untouched holdout, establish source timing, or prove complete blindness. Source outcome producer/clock authority remains unverified. Keep the exact immutable input and resolution source plus their original producer receipts at their canonical location; this helper does not create another copy. The output is **retrospective source-only diagnostic feedback**, not a paper settlement, fill, economic return, or promotion recommendation.
