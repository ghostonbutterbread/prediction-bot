# Daily research agent runbook

`scripts/daily_research.py select` chooses the first not-yet-completed **content pair** from an operator-supplied, ordered JSON catalog of bounded, already projected collector-derived replay inputs and separate outcomes. Update the catalog as new bounded exports become available; it does not run a collector, discover input files, establish source provenance, or turn an append-only live file into a trustworthy snapshot. Input must be nonempty; outcomes may be empty. A changed input **or** outcome hash is a new pair, not necessarily an independent opportunity or statistically new evidence. Put newest preferred exports first. Paths must be absolute, frozen files and outside the state directory. Example:

```json
[{"inputs":"/absolute/frozen-inputs.jsonl","outcomes":"/absolute/frozen-outcomes.jsonl"}]
```

Selection copies the bytes actually read to a task-owned persistent directory and records source paths and hashes. It bounds each read to the specified byte limit plus one; neither these limits nor the CLI's row limit bound CPU, memory amplification or elapsed time. A file being modified during reading is not a trustworthy snapshot; the caller must supply stable immutable exports. The store is a cooperating-agent mechanism, not a sandbox, a concurrent lock, a crash-atomic transaction, a tamper-proof ledger or a protection against malicious code. Run only one job at a time. An interrupted selection returns `in_progress`; inspect its manifest and frozen file hashes before resuming; if missing or mismatched, preserve it and stop for operator reconciliation. Do not create `complete.json` to bypass a failure. Only complete a pair after the comparison and any requested queue entry have actually succeeded. Errors have a nonzero exit and stderr; an empty or fully completed catalog returns `no_new_data`. Retain experiments and queues; decide retention/archival before enabling a recurring job.

## Agent instruction for a daily Hermes cron session

The job prompt should point to this runbook in a reviewed, clean, pinned checkout and provide (1) a catalog, (2) an **owned persistent derived** work root, (3) row and input/outcome byte budgets, and (4) a preinstalled Docker image ID. Verify these values are separate from raw collector archives, services, accounts, all other worktrees and protected roots; do not use a runtime checkout as the output root. The job is the model-driven agent: do not start another `hermes` CLI, gateway or optimizer. This is an instruction for later configuration, **not an activated schedule**.

1. Record `git status --porcelain` (must be empty), `git rev-parse HEAD`, `git rev-parse HEAD^{tree}`, the checkout path, image ID, configured limits and hypothesis context in a unique journal under the owned work root. The exact clean commit is the baseline. Stop on a dirty source checkout or missing catalog/image. No fetch, checkout, reset, service or config change in the source checkout.
2. Run `python3 scripts/daily_research.py select --catalog "$CATALOG" --state "$WORK/selections" --max-input-bytes "$INPUT_BYTES" --max-outcome-bytes "$OUTCOME_BYTES"`. Save its JSON in the journal. For `no_new_data`, stop and report it. For `in_progress`, resume only after validating all frozen hashes and prior journal state; otherwise stop with an explicit incomplete/error report. For `selected`, retain the returned directory as `D`. The two frozen files are `D/inputs.jsonl` and `D/outcomes.jsonl`.
3. Create **two new local, task-owned Git clones** of the clean checkout at the recorded commit: `git clone --no-hardlinks --no-local "$CHECKOUT" "$D/baseline"` and likewise `"$D/experiment"`; in each `git checkout --detach "$BASE"`. Verify HEAD/tree and clean status. In the experiment clone make a named local branch, e.g. `git switch -c research/daily`, and record it. Do not edit baseline. These clones preserve reachable candidate commits and avoid changes to other worktrees. No fetch or push.
4. Before looking at outcomes, inspect decision inputs and existing code and propose a falsifiable hypothesis with rationale and expected effect. The agent may edit any versioned source, lane, strategy, composition, tests or replay adapter; no canned search or artificial path allowlist. Add focused tests first, show RED/GREEN, commit all changes in the experiment clone, and record its commit/tree and test output. A change outside the actual source-only call path can legitimately have no effect. Adapt the replay interface if needed, but do not claim unsupported full-strategy/composition replay. Do not write or access accounts, raw data, services, scheduler or live trading. Never manipulate source clocks or run either approval-blocked chronological-wallet or future-source-clock probe (including equivalents).
5. Execute baseline and candidate with identical frozen inputs/outcomes and limits using the real CLI. Use an isolated execution root `D/runtime` with `collector/data/derived_reports/research` as the store, and record stdout/stderr and exit status separately under `D`. A safe local-image pattern for **each** run is below; set `CODE` to the respective clone, `IDEA` to the hypothesis, and `MAX_ROWS` explicitly. The selected source files and code are mounted read-only; the container has no network, no host HOME or credentials, and no privileged access. Test commands should use the same isolation and `--entrypoint` as appropriate. Arbitrary experiment code is still untrusted: do not mount sensitive paths or the Docker socket; Docker is a containment layer, not a proof of noninterference. Check local Docker/image suitability before use.

```sh
mkdir -p "$D/runtime/collector/data/derived_reports"
docker run --rm --network none --read-only --tmpfs /tmp:rw,nosuid,nodev,size=256m \
  --cap-drop ALL --security-opt no-new-privileges --pids-limit 256 --memory 2g \
  --user "$(id -u):$(id -g)" --entrypoint /opt/hermes/.venv/bin/python3 \
  -e HOME=/tmp -e PYTHONDONTWRITEBYTECODE=1 -e PREDICTION_BOT_COLLECTOR_ROOT=/work/runtime/collector \
  --mount "type=bind,src=$CODE,dst=/work/code,readonly" \
  --mount "type=bind,src=$D/inputs.jsonl,dst=/work/inputs.jsonl,readonly" \
  --mount "type=bind,src=$D/outcomes.jsonl,dst=/work/outcomes.jsonl,readonly" \
  --mount "type=bind,src=$D/runtime,dst=/work/runtime" \
  --workdir /work/code "$IMAGE" scripts/auto_research.py run \
  --store /work/runtime/collector/data/derived_reports/research \
  --inputs /work/inputs.jsonl --outcomes /work/outcomes.jsonl --idea "$IDEA" \
  --max-rows "$MAX_ROWS" --max-input-bytes "$INPUT_BYTES" --max-outcome-bytes "$OUTCOME_BYTES"
```

Use the baseline CLI in the same container layout to run `compare --store /work/runtime/collector/data/derived_reports/research BASELINE_ID CANDIDATE_ID`; save the unmodified JSON and both run receipts. Compare validates saved artifact hashes and matching selected identities/settings; it does **not** establish an independent opportunity roster. If there is no change, a test fails, a run errors, or identities do not match, record that honestly and do not queue it as supported. The model may inspect results and formulate more hypotheses on the same frozen pair; commit and run each candidate separately, preserving each receipt. Outcomes must be absent when decisions are generated for any genuinely blind experiment; this existing CLI reads outcomes in the same process as decision generation, so arbitrary code cannot be claimed blinded. For comparison only, baseline and candidate see the exact same frozen pair.

6. For a candidate worth human review, run the same container command with the `queue` subcommand, `--store ... --experiment CANDIDATE_ID --note 'manual review only; source time unverified'`. Queue is non-overwriting and append-only in the existing SQLite store. Never activate it. For an optional paper handoff, report candidate commit, exact provenance, tests, comparison, limitations and the need for a separately reviewed version-aware forward adapter and existing champion/pending-position preservation; do not touch paper accounts.
7. Save an immutable-by-convention `D/complete.json` with exclusive creation (`open(..., 'x')`), containing baseline/candidate commit and tree IDs, experiment IDs, comparison/queue receipts, hypothesis, tests, and an explicit conclusion. Never overwrite it. If any step errors, leave it absent, report `in_progress`/error and the exact resume point; preserve failed outputs. A completion marker is an agent assertion, not independently verified by `select`. Report all evidence as source-time unverified and diagnostic-ineligible, even when selected rows match. No quote is a fill and no profit, forward validation, promotion or activation follows.

The current CLI runs source-probability control and Source Router source-only replay; it is not the production decision pipeline, a general strategy/composition executor, or a chronological wallet. It does not validate source availability clocks and has no complete blindness guarantee. It requires a separate authorized effort to supply these missing interfaces and prove source timing. Its store references input paths and hashes; retain the frozen pair, container image and environment needed to reproduce results. Manual review is required before integrating, scheduling or activating this workflow.
