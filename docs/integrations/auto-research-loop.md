- Intent: an agent can manually propose a hypothesis, commit arbitrary changes in its own code checkout, replay a *frozen identical* decision-input and outcome pair, inspect matched control/candidate outputs, and queue a review handoff. This is a small runnable research slice, **not** an autonomous agent, scheduler, learner, model-training system, or promotion mechanism.
- `scripts/auto_research.py` calls the existing `run_collector_source_router_replay` path in a directional-only mode that excludes P&L while retaining quote and fixed-stake fields for diagnostic context. It runs source-probability control and Source Router candidate on selected projected identities. It is **not** the full DecisionPipelineEvaluator, a production strategy replay, a composition interface, the paper wallet, or a chronological wallet. Code experiments execute by committing them in a checkout containing this CLI and invoking that checkout's CLI; it does not check out, sandbox, build, or orchestrate other Git versions. The agent may edit arbitrary versioned code, but changes not on this actual call path have no effect. The existing replay requires its expected output contract; incompatible changes require adapting this CLI too. Compositions are not wired here.
- `compare` requires equal full input/outcome hashes, selection settings, and unique identical sealed decision identities. It verifies saved artifact hashes and reports counts plus selected-object coverage. Without an independent opportunity roster `matched_inputs_and_settings` is always false; `selected_rows_matched` only describes a nonempty selected subset without invalid identities, not a complete opportunity universe. Empty and omitted-identity cases never match. All outputs are diagnostic-ineligible pending source-clock proof.
- `queue` only inserts a handoff record. It does not touch, read, replace, or select a paper champion, paper accounts, pending positions, or live state. Existing forward-paper combination support is narrow; no safe general version-aware forward adapter or delayed settlement attribution is implemented or proven here. A paper champion and its pending positions require their existing version binding to remain untouched and independent explicit review before any new cohort is created. The synthetic test checks a paper-state sentinel, not the real paper APIs.

## Prerequisites and invocation

Use the project's installed dependencies and a **clean committed checkout** including this CLI. Set `PREDICTION_BOT_COLLECTOR_ROOT` explicitly to the intended isolated research root; the store must be strictly beneath its `data/derived_reports`. Supply a previously exported canonical replay-decision-input JSONL and separate finalized-outcome JSONL. Preserve both files: the replay verifies input canonical hashes and performs an additional recursive forbidden-field screen, but a self-hash/classifier cannot prove provenance, source time, completeness, or outcome authority. Projector-created legacy snapshot/candidate identities may be synthetic raw-row-hash identities; do not describe them as proven collector publication identities or forward cohort matches. No selector-history manifest is wired here, so the source-router candidate may skip for missing history.

```sh
export PREDICTION_BOT_COLLECTOR_ROOT=/absolute/isolated/research-root
STORE="$PREDICTION_BOT_COLLECTOR_ROOT/data/derived_reports/auto-research"
python scripts/auto_research.py run --store "$STORE" --inputs /absolute/decision-inputs.jsonl \
  --outcomes /absolute/finalized-outcomes.jsonl --idea 'hypothesis and reason' --max-rows 100 \
  --max-input-bytes 1000000 --max-outcome-bytes 1000000
# Commit a proposed change in its own checkout, use the same STORE and exact files/settings,
# and invoke that checkout's scripts/auto_research.py run. Capture both experiment IDs.
python scripts/auto_research.py compare --store "$STORE" FIRST_EXPERIMENT_ID SECOND_EXPERIMENT_ID
python scripts/auto_research.py queue --store "$STORE" --experiment SECOND_EXPERIMENT_ID --note 'manual review only'
```

Each completed run gets a unique derived directory and an SQLite `experiments` row with commit/tree, SHA-256 input/outcome and artifact hashes, explicit replay settings, Python version, and replay summary. `candidate_queue` references a completed experiment. SQLite update/delete triggers prevent ordinary modification through these tables, while the artifact hashes detect altered files at comparison. **Neither SQLite triggers nor writable files are a tamper-proof or immutable storage system**: an administrator can modify the DB/schema or replace both records and files. Git objects must remain reachable; input/outcome files are referenced and hashed, not copied. Interpreter, dependencies, ignored files, and ambient environment are not fully pinned. Clean `git status` does not cover ignored files. Reproduction needs the original files, Git object, compatible dependencies, and a controlled environment. The before/after hashes detect ordinary concurrent changes, not an adversarial change-and-restore race. Interrupted or failed runs can leave unregistered derived directories and need manual inspection, never deletion of raw evidence.

This tool is not a code security sandbox. Only run reviewed, trusted experiment commits in an isolated environment without trading credentials/network. The current underlying source-only builder deliberately ignores supplied outcomes while producing decisions, but the process reads the outcome ledger before invoking it; arbitrary changed code can violate that boundary. The recursive screen is defense in depth, not a positive-schema proof for arbitrary self-hashed JSON. Source availability clocks and all strategy dependencies are not independently verified here. No promotion-grade blindness claim follows from these tests.
